# Dooray Task Reservation

Dooray 업무·댓글 작업을 **예약**해 두면, 예약 시각에 자동으로 실행해 주는 크롬 익스텐션입니다.
서버 없이 완전히 클라이언트(브라우저)만으로 동작합니다.

## 지원 기능

| 대상 | 작업 |
|------|------|
| 업무(Task) | 생성 · 수정(제목/본문) · 삭제* |
| 댓글(Comment) | 작성 · 수정 · 삭제 |
| 첨부파일 | 업무 생성/수정, 댓글 작성/수정 시 첨부 (이미지는 본문·댓글에 인라인 표시) |
| 멘션 | 멤버 이름 검색 후 본문/댓글에 @멘션 삽입 (서버가 알림 발송) |

모든 작업에 예약 시각을 지정할 수 있으며, 예약 시각이 되면 자동으로 Dooray API를 호출합니다.
sota.dooray.com 실계정으로 인증·업무 생성/수정·댓글 CRUD·첨부 업로드·인라인 이미지·멘션이
전부 실측 검증되었습니다.

\* 업무 삭제는 Dooray 공개 API에서 지원되지 않는 것으로 **실측 확인**되었습니다
(DELETE 요청 시 404). 예약해도 실패할 가능성이 높으며, 웹 UI에서 직접 삭제해야 합니다.

### 첨부파일 동작 방식

- 파일은 예약 등록 시 브라우저 저장소에 보관했다가, 실행 시각에 Dooray 파일 서버
  (`file-api.{cloud}/uploads/...`)로 업로드합니다 (총 25MB 이하).
- Dooray에는 댓글 전용 첨부 API가 없어, 댓글 첨부는 업무(post)에 파일을 올린 뒤
  댓글 본문에서 `![이름](/files/{id})` 형식으로 참조하는 방식(공식 CLI와 동일)을 사용합니다.
- 이미지 확장자(png/jpg/gif/webp 등)는 인라인 이미지로, 그 외 파일은 링크로 삽입됩니다.
- 페이지 에디터([⏰ 예약] 버튼)에서 캡처한 내용은 **Dooray 네이티브 마크다운으로 변환**됩니다
  (아래 참조). 에디터에 삽입한 인라인 이미지는 캡처 시 내려받아 실행 시각에 대상 업무의
  정식 첨부로 재업로드한 뒤 본문 참조를 교체합니다 (임시 파일 참조로 인한 깨짐 방지).

### 저장 형식 — 왜 마크다운인가

Dooray 웹 UI가 실제로 저장하는 댓글·본문은 예외 없이 `text/x-markdown` 입니다
(실계정 기존 댓글 전수 확인). `text/html` 로 보내면 서버가

- **멘션을 해석하지 않아** 죽은 링크가 되고 알림이 가지 않으며,
- `<pre>` 안의 **줄바꿈을 공백으로 접어** 코드 블록이 깨집니다.

그래서 에디터 내용은 Dooray 마크다운으로 변환해 전송합니다
(`editor-markdown.js`). 변환이 보장하는 항목:

| 작성 요소 | 저장 형식 |
|-----------|-----------|
| 텍스트·굵게·기울임·취소선 | `**굵게**` `*기울임*` `~~취소~~` |
| 제목 / 인용 / 구분선 | `# 제목` · `> 인용` · `---` |
| 하이퍼링크 | `[텍스트](URL)` |
| 인라인 코드 / 코드 블록 | `` `code` `` · ```` ```lang ```` (줄바꿈·들여쓰기 보존) |
| 목록 (중첩·체크리스트) | `- ` / `1. ` / `- [x] ` |
| 표 | 마크다운 파이프 표, 병합 셀은 원본 `<table>` HTML |
| 이미지 | `![이름](/files/{id})`, 크기 지정 시 `<img … width>` |
| 멘션 | `[@이름](dooray://{orgId}/members/{id} "member")` |

### 멘션 동작 방식

- 팝업의 본문/댓글 입력란 아래 **@추가** 버튼으로 멤버 이름을 검색해 멘션을 삽입합니다.
- 삽입 형식: `[@이름](dooray://{orgId}/members/{memberId} "member")` — 서버가 이 마크업을
  인식해 org ID를 정규화하고 알림을 발송하는 것을 실측 확인했습니다.
- Dooray 페이지 에디터에서 @멘션으로 작성한 경우, 캡처 시 에디터 DOM에서 멤버 ID를 찾아
  같은 마크업으로 복원합니다. ID를 못 찾으면 **이름으로 멤버 API를 조회**해 채우고,
  동명이인이거나 조회에 실패하면 예약 모달에 경고를 표시합니다.

## 설치

> 📖 **스크린샷이 포함된 상세 가이드: [docs/INSTALL.md](docs/INSTALL.md)**

1. 크롬에서 `chrome://extensions` 접속
2. 우측 상단 **개발자 모드** 켜기
3. **압축해제된 확장 프로그램을 로드** 클릭 → 이 폴더 선택

## 초기 설정

1. 툴바의 시계 아이콘 클릭 → **설정** 탭
2. **Dooray URL** 입력 (예: `https://sota.dooray.com`)
3. **API Key** 입력
   - 발급 위치: Dooray 웹 접속 → 우측 상단 톱니(설정) → **API** 메뉴 → **개인 인증 토큰** 생성
4. **저장** 후 **연결 테스트**로 인증 확인

민간(`*.dooray.com`) / 공공(`*.gov-dooray.com`) / 금융(`*.dooray.co.kr`) 클라우드는
URL만 넣으면 API 주소가 자동 매핑됩니다. 자체 설치형 Dooray는 입력한 도메인으로
직접 호출하며, 저장 시 해당 도메인 접근 권한을 추가로 요청합니다.

## 사용 방법

### 방법 1 — Dooray 페이지에서 바로 예약 (에디터 통합)

Dooray 페이지의 에디터(댓글 작성, 본문 수정, 업무 생성) 하단 **저장 버튼 옆에
[⏰ 예약] 버튼이 자동으로 추가**됩니다. 에디터에 내용을 작성한 뒤 [⏰ 예약]을 누르면
작성 내용이 마크다운으로 캡처되고, 예약 시각만 골라 등록하면 됩니다.

- 업무 상세 화면에서는 대상 업무가 자동 감지됩니다 (댓글 작성 / 본문 수정)
- 업무 생성 화면에서는 프로젝트와 제목을 선택해 새 업무 생성을 예약합니다
- 모달의 **보낼 내용** 칸에 변환 결과가 그대로 보이며, 등록 전에 직접 고칠 수 있습니다
- 멘션 인식 결과·인라인 이미지 개수·첨부 총 용량이 칩으로 함께 표시됩니다

### 방법 2 — 익스텐션 팝업에서 예약

1. **새 예약** 탭에서 작업 유형 선택 (업무 생성/수정/삭제, 댓글 작성/수정/삭제)
2. 프로젝트 → 업무 → 댓글 순으로 대상 선택 (목록에 없으면 "ID 직접 입력…" 선택)
3. 내용과 **예약 시각** 입력 후 **예약 등록**
4. **예약 목록** 탭에서 대기/완료/실패 상태 확인, 재시도·삭제·즉시 실행 가능

실행 결과는 크롬 알림으로도 표시됩니다.

## 동작 원리와 제약

- 예약은 `chrome.storage.local`에 저장되고 `chrome.alarms`로 스케줄링됩니다.
  별도 서버가 없으므로 **예약 시각에 크롬이 실행 중이어야** 전송됩니다.
- 예약 시각에 크롬이 꺼져 있었다면, **다음에 크롬을 켰을 때 밀린 예약을 자동 전송**합니다.
- 업무 수정은 실행 시점에 기존 업무를 먼저 조회한 뒤 담당자·태그·마일스톤 등을
  그대로 유지하면서 제목/본문만 교체합니다 (Dooray의 업무 수정 API가 전체 교체 방식이기 때문).
- API Key는 이 브라우저 프로필의 확장 프로그램 저장소에만 보관되며 외부로 전송되지 않습니다
  (Dooray API 호출에만 사용).

## 파일 구조

```
manifest.json        # MV3 매니페스트
background.js        # 서비스 워커: 예약 스케줄링(chrome.alarms) + Dooray API 호출
editor-markdown.js   # 에디터 DOM → Dooray 마크다운 변환기
content.js           # Dooray 페이지 에디터에 [⏰ 예약] 버튼 삽입 + 예약 모달
popup/               # 예약 등록 · 목록 · 설정 UI
icons/               # 아이콘
tests/               # 단위 · 실계정 통합 · 브라우저 UI 테스트
```

## 테스트

```bash
npm install
npm test             # 단위 테스트 (jsdom) — 마크다운 변환 + 예약 로직
npm run test:ui      # 브라우저 UI 테스트 (Puppeteer) — 예약 모달 + 팝업 + 패키지
npm run test:package # 배포 패키지를 실제 Chrome 에 설치해 검증
npm run test:live    # 실계정 통합 테스트 — .env 의 TEST_KEY_CODE 사용
```

`test:live` 는 실제 Dooray에 테스트 업무를 만들고 댓글을 답니다.
기본 대상은 개인 프로젝트이며 `DTR_TEST_PROJECT` 환경 변수로 바꿀 수 있습니다.
`.env`(API Key)는 커밋되지 않도록 `.gitignore`에 포함되어 있습니다.

## 빌드 · 배포

```bash
npm run build                            # dist/dooray-task-reservation-{version}.zip
npm run build -- --out dist/extension.zip # 경로 지정
```

빌드는 **manifest가 실제로 참조하는 파일만** 담습니다 (현재 10개 파일 / 약 33KB).
테스트·문서·개발 스크립트·`node_modules`·`.env` 는 들어가지 않습니다.
파일 목록을 손으로 관리하지 않고 `manifest.json`과 `popup.html`을 파싱해 자동으로
수집하므로, 소스를 추가해도 패키징에서 누락되지 않습니다.

빌드 시 자동 검사하는 항목:

- manifest가 참조하는 파일이 모두 존재하는지, 버전 형식이 올바른지
- 팝업이 외부 리소스(CDN 등)를 참조하지 않는지 — 스토어 정책 위반 방지
- `debugger` 문 잔존 여부
- 완성된 zip에 예상 목록 외 파일이 섞이지 않았는지

`npm run test:package` 는 여기서 더 나아가 **만들어진 zip을 실제 Chrome에 설치**해
서비스 워커 등록·팝업 렌더·Dooray 도메인에서의 content script 주입까지 확인하고,
자격증명 문자열 포함 여부와 권한 범위도 점검합니다.

### 스토어 업로드

1. `chrome://extensions` → **압축해제된 확장 프로그램을 로드** 로 최종 확인
2. [Chrome Web Store 개발자 대시보드](https://chrome.google.com/webstore/devconsole)에 zip 업로드

`v*` 태그를 푸시하면 GitHub Actions가 테스트 → 패키지 검증 → 업로드까지 자동 수행합니다
(`.github/workflows/release.yml`, `CWS_*` 시크릿 필요).

git tag v1.3.0 && git push --tags
```
